# Troubleshooting FAQ

> Fictional FAQ for RAG testing.

## 1. Slow Application
Refresh the page, check the network, and retry.

## 2. Login Error
Verify credentials and check whether the account is locked.

## 3. Password Reset Failure
Confirm the account email and request a new reset link.

## 4. Upload Failure
Confirm the file type, file size, and network connection.

## 5. Unsupported File
Check the documented list of supported file formats.

## 6. HTTP 400
A 400 response generally indicates that the request is invalid or malformed.

## 7. HTTP 401
A 401 response generally indicates missing or invalid authentication.

## 8. HTTP 403
A 403 response generally indicates that the authenticated user is not permitted to perform the requested operation.

## 9. HTTP 404
A 404 response generally indicates that the requested resource could not be found.

## 10. HTTP 429
A 429 response indicates that the request rate exceeded an applicable limit. Reduce request frequency and use backoff.

## 11. HTTP 500
A 500 response indicates an internal server error. Retry later and contact support if it persists.

## 12. Changes Not Saved
Confirm that the save operation completed and refresh the page.

## 13. Missing Data
Refresh the application and verify that the correct account or project is selected.

## 14. Browser Compatibility
Use a supported, up-to-date browser.

## 15. Cache Problem
Clear cached site data and retry if stale content is suspected.

## 16. Extension Conflict
Temporarily disable browser extensions to determine whether one is interfering with the application.

## 17. Network Problem
Test another network or verify that required domains are reachable.

## 18. API Timeout
Increase the client timeout only when appropriate and investigate slow downstream dependencies.

## 19. Repeated API Failures
Record the endpoint, status code, timestamp, and request identifier before contacting support.

## 20. Service Unavailable
Check the service status page if one is available and retry after a short interval.

## 21. Unexpected Error Message
Capture the exact error text instead of paraphrasing it when opening a support ticket.

## 22. Duplicate Operation
Check whether the original request succeeded before submitting the same operation again.

## 23. File Processing Stuck
Verify file size and format, then retry with a smaller test file if possible.

## 24. Escalating an Issue
Provide account email, reproduction steps, timestamps, error messages, and relevant identifiers to support.
